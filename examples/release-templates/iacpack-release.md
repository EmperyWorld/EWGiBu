# iacpack release checklist (human-controlled)

This file is generated by `iacpack release init-templates` (ADR-019). It does
**not** publish anything. GitHub release, tags, and signing stay operator-owned.

## Local package

1. Review `iacpack.yaml` (and lockfile) — no secret values.
2. `iacpack validate --workspace .`
3. `iacpack lock --workspace .`
4. `iacpack build --workspace .`
5. `iacpack verify` against the produced directory/bundle.

## CI

- Workflow `.github/workflows/iacpack-ci.yml` runs validate/lock/build/verify only.
- No deploy, `gh`, push, or registry publish jobs are included by default.
- Action versions are pinned by full commit SHA — do not float to `@main`.

## Human publish (outside iacpack)

1. Create an annotated tag on the reviewed commit.
2. Build reproducible release artifacts on a trusted host (or CI release job you add).
3. Sign artifacts with your own identity (cosign/GPG as you choose).
4. Create the GitHub Release manually (web UI or your own signed tooling).
5. Attach SBOM/provenance checksums; never paste secret values into release notes.

## Never

- Do not commit populated `.env` files.
- Do not enable privileged containers, Docker socket mounts, or host binds without review.
- Do not add unpinned GitHub Actions (`@main` / `@master`).
- Do not expect iacpack itself to push, tag, or publish.
